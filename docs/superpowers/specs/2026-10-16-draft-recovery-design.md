# 未保存内容自动暂存与恢复（B1）

日期：2026-10-16
状态：已批准（用户：像 Win11 记事本一样直接恢复、不询问；正常点 × 关闭仍询问保存）
进度：`docs/STATUS.md`

## 1. 目标

Windows 注销、关机、Reader 崩溃或被强制结束时，未保存的编辑内容（包括未命名草稿）不丢；下次启动 Reader 时直接把这些标签恢复出来，标签上带 `*`，不弹窗询问。

## 2. 行为

- 范围：可编辑的文本类标签，即 Markdown 编辑视图（已有文件和未命名草稿）与文本/代码编辑视图（已有文件和未命名文本）。终端、浏览器、预览类标签不在范围内。
- 暂存：标签变成「有未保存修改」后，内容在停止输入约 1 秒后写入暂存；应用失去焦点时立即把待写的暂存写完。
- 删除暂存：保存成功、撤销回到已保存状态、关闭标签（用户选了保存或不保存）、正常关闭窗口时都删除对应暂存。
- 正常关闭（点 ×、关闭标签）：照旧询问「保存 / 不保存 / 取消」，不改变。
- 注销/关机：Qt 的 `commitDataRequest` 到来时立即把所有未保存内容写入暂存，并标记「会话结束」；此后窗口关闭不再弹保存询问，暂存保留。
- 恢复：Reader 主进程启动时，如果暂存目录里有内容，说明上次被意外打断：在启动的第一个窗口里（无论是空启动还是双击文件）为每份暂存打开一个标签，内容为暂存内容，标签带 `*`，保持原文件路径（`Ctrl+S` 直接存回原文件）和原编码/换行；状态提示「已恢复 N 个未保存的标签」。如果原文件在暂存之后被别处改过，提示里注明。
- 标签在窗口之间移动不影响暂存（按文档编号存放，与窗口无关）。

## 3. 存储

- 目录：`<数据目录>\drafts\`（数据目录与「最近打开」相同：`READER_DATA_DIR` 或 `%LOCALAPPDATA%\Reader`）。
- 每份暂存一个 JSON 文件 `<文档编号>.json`，先写临时文件再原子替换：`{"version": 1, "kind": "markdown"|"text", "path": 路径或 null, "suffix", "title", "text", "encoding", "bom", "newline", "lossless", "file_mtime_ns", "file_size", "saved_at"}`。
- 读取时跳过损坏或版本不认识的文件（保留在原处，不删除）。

## 4. 不做

- 不恢复终端、浏览器、只读预览标签，不恢复窗口位置。
- 不改变正常关闭时的保存询问。

## 5. 测试

- 暂存存取：原子写、读取全部、删除、损坏文件跳过。
- 视图：取快照、按快照恢复（脏标记、路径、编码换行保留，`Ctrl+S` 写回原文件）。
- 窗口：编辑后约 1 秒写入、保存/撤销到干净/关闭标签后删除、失去焦点立即写、标签移动后仍正确暂存。
- 应用：启动时恢复到第一个窗口；会话结束时写入全部暂存且关闭不弹询问。
- 冻结构建冒烟照常通过。
